# ReinforceBean

**이 트래픽에 이 서버 설정이면 충분한가**를 브라우저에서 실험해 보는 시뮬레이터.

---

## 1. 프로젝트 개요

운영 중인 서버에서는 "커넥션 풀을 10에서 3으로 줄이면 어떻게 되나"를 실험할 수 없다.
이 프로젝트는 그 실험을 브라우저 안에서 대신한다.

### 무엇을 넣나

| 넣는 것 | 예 |
|---|---|
| 트래픽 | 평균 150 rps, 시간대별 곡선(위키백과 등 실제 모양) |
| 작업 구성 | 상품 조회 90% (20ms) + 복잡 검색 10% (150ms) |
| 서버 설정 | 워커 스레드 50, DB 커넥션 10, 대기 큐 100, DB 시간 30ms |

### 무엇이 나오나

| 나오는 것 | 예 |
|---|---|
| 어디가 먼저 막히는가 | DB 커넥션 (이용률 0.86, 스레드는 0.50) |
| 몇 rps에서 무너지는가 | 커넥션 10이면 316 rps, 20이면 450 rps 이상 |
| 어느 설정이 나은가 | 스레드만 2배 → 효과 없음 / 커넥션 증설 → 효과 있음 |
| 어떤 인스턴스가 필요한가 | t4g.small + db.t4g.xlarge = 약 $312/월 |

### 왜 예측을 믿을 수 있나

`validation/` 에 시뮬레이터와 **같은 구조로 만든 실제 서버**(대기 큐 → 스레드 → SQLite 커넥션 풀)가 있다.
여기에 진짜 부하를 걸어 나온 실측값으로 모델을 보정하고, **보정에 쓰지 않은 rps**에서 예측이 맞는지 확인한다.
(holdout 평균 오차 약 27% → 9%)

### 어떻게 돌아가나

브라우저만 있으면 된다. 백엔드도 빌드 도구도 없이 정적 파일 4개가 전부다.

```
index.html    화면 구조 + 스타일
engine.js     시뮬레이션 엔진 · 병목 판정 · 그림 그리기
advisor.js    설정 비교 · 최소 자원 탐색 · 실측 보정 · 인스턴스 추천
app.js        UI 연결 · 메인 루프 · 데이터 로딩
```

## 2. 실행 방법

### 가장 빠른 방법 — 그냥 열기

`index.html` 을 브라우저로 더블클릭하면 시뮬레이션은 전부 동작한다.
(단, 공개 트래픽 곡선은 브라우저 보안 정책 때문에 못 읽는다)

### 권장 — 로컬 서버로 열기

```bash
python -m http.server 8000        # 또는: npx serve
# → 브라우저에서 http://localhost:8000
```

이러면 `data/` 의 공개 트래픽 곡선까지 전부 쓸 수 있다.

> **처음이라면** 화면 왼쪽 위 **「예제 실행」** 버튼을 누르면 된다.
> 조건 설정 → 병목 판정 → 설정 비교 → 실측 보정 → 인스턴스 추천까지
> 약 35초 동안 자동으로 한 바퀴 돈다. 실측 CSV가 없으면 내장 샘플을 쓰므로
> 파일을 그냥 열어도 끝까지 돈다.

### 공개 데이터 새로 받기 (선택)

`data/` 에 이미 받아둔 파일이 들어 있다. 갱신하고 싶을 때만 실행한다.

```bash
node validation/fetch_public.js            # 전부 (Node 22+)
node validation/fetch_public.js --list     # 받을 수 있는 목록 보기
```

받는 것: 위키백과 트래픽 곡선, TechEmpower 벤치마크, AWS 서울 리전 EC2/RDS 가격.

### 실제 서버로 검증하기 (선택)

시뮬레이션 결과를 진짜 측정값과 맞춰보고 싶을 때. 터미널 두 개가 필요하다.

```bash
# ① 검증 서버 띄우기 (기본: 스레드 50 · 커넥션 10 · 큐 100 · DB 30ms · 포트 8080)
node validation/server.js

# ② 다른 터미널에서 부하 걸기 → result.csv 생성
node validation/load.js --out result.csv

# ③ 보정 + 검증 (선택 — 화면에서도 같은 일을 할 수 있다)
node validation/compare.js result.csv --alpha 0.39 --fit 50,250,400
```

만들어진 `result.csv` 는 화면의 **「실측 CSV」** 버튼으로 그대로 불러올 수 있다.

설정을 바꿔서 띄우려면 환경변수를 앞에 붙인다.

```bash
THREADS=200 CONNS=10 node validation/server.js
MIX="상품조회:0.9:20,복잡검색:0.1:150" node validation/server.js
```

## 3. 시각화 방식

### 화면 배치

한 페이지에 전부 들어가고 스크롤이 없다.

```
┌ ① 조건 › ② 병목 › ③ 설정 비교 › ④ 최소 자원 › ⑤ 개선안 › ⑥ 보정 › ⑦ 인프라 › ⑧ 저장 ┐
├──────────┬────────────────────────────────┬──────────────────────────┤
│ 왼쪽      │ 가운데 위 — 후보 비교 표          │ 오른쪽 — 분석 결과         │
│ 입력      │   설정 여러 벌을 한 표에          │   병목 판정 · 지표         │
│          ├────────────────────────────────┤   최소 자원 탐색           │
│ 트래픽    │ 가운데 — 서버 단면도              │   실측 보정               │
│ 작업 구성  │   스레드│커넥션│대기 큐│요청 수지   │   인스턴스 추천            │
│ 서버 설정  │   ─── 지연 분해 ───              │                          │
│ 후보 목록  ├──────────────┬─────────────────┤                          │
│          │ 타임라인       │ 성능 곡선         │                          │
└──────────┴──────────────┴─────────────────┴──────────────────────────┘
  [일시정지] [처음으로]   시뮬 22.3s  ━━━●━━━  표시 구간 [60초 ▾]
```

왼쪽에서 조건을 바꾸면 가운데가 실시간으로 움직이고, 버튼을 누르면 오른쪽에 분석 결과가 쌓인다.

### 자원마다 그림을 다르게 쓴다

같은 막대그래프로 다 그리면 "무엇을 봐야 하는지"가 안 보인다. 자원의 성질에 맞는 그림을 각각 쓴다.

| 무엇 | 성질 | 그림 | 읽는 법 |
|---|---|---|---|
| **스레드** | 정해진 슬롯을 몇 개 쓰는가 | 도트 매트릭스 | 칸 하나가 스레드 하나. 채워진 칸 = 일하는 중 |
| **커넥션** | 같은 슬롯 문제, 개수가 적다 | 도트 매트릭스 (칸이 큼) | 전부 차면 스레드가 아무리 많아도 소용없다 |
| **대기 큐** | 지금 값보다 *쌓이고 있는가* | 스파크라인 (면적) | 선이 우상향이면 적체 중 |
| **요청 수지** | 유입이 어디로 갈라졌나 | 분기 흐름 (생키) | 왼쪽 기둥(유입)이 완료·실패·낭비로 갈라진다 |
| **지연 분해** | 한 건의 시간이 어디서 나갔나 | 100% 가로 띠 | 큐·커넥션 대기·DB·CPU 중 어디가 넓은지 |

**「낭비」가 이 화면의 숨은 주인공이다.** 클라이언트가 타임아웃으로 포기해도 서버는 그 요청을 끝까지
처리한다. 이 낭비가 용량을 갉아먹어 재시도 폭풍이 스스로 유지된다.

### 색 규칙

- 기본은 **회색 농담 + 파랑 하나**. 색을 아껴서 정말 중요한 것만 튀게 한다.
- **주황**은 75% 넘게 찼을 때, **빨강**은 90%를 넘거나 한계를 벗어났을 때만 쓴다.
- 표에서는 나쁜 칸일수록 배경이 붉어진다. 숫자를 읽기 전에 어디가 문제인지 보인다.

### 시간축 두 개

| 차트 | 가로축 | 무엇을 보나 |
|---|---|---|
| **타임라인** | 시간 (초) | 스파이크·슬로우 쿼리 같은 사건이 **언제** 벌어졌나 |
| **성능 곡선** | 유입 (rps) | 이 설정이 **몇 rps에서** 무너지나 |

- 타임라인은 위아래 두 칸이다. 위는 처리량(유입·완료·실패·재시도), 아래는 응답시간(p50·p95).
  마우스를 올리면 그 시점의 모든 값이 툴팁으로 뜬다. 세로 점선은 시나리오 단계 표시다.
- 성능 곡선은 설정 후보를 **겹쳐** 그린다. 가로 점선이 목표 p95,
  세로 점선이 그 선을 넘는 rps — 즉 **"이 설정이 무너지는 지점"** 이다.

### 숫자만 남긴 오른쪽 패널

오른쪽 분석 패널은 해설 문장 없이 **수치와 표만** 보여준다.
표 자체가 답이 되게 하고, 읽는 사람이 문장에 끌려가지 않게 하기 위해서다.

왼쪽 입력과 가운데 비교표에는 짧은 도움말이 붙어 있는데, 이건 화면 오른쪽 위
**「설명」** 체크박스로 켜고 끌 수 있다. 기본은 꺼짐(숫자만)이다.
